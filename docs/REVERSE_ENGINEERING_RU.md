# Использование reverse engineering

При переработке использовались реверс-инжиниринг и анализ форматов и поведения StarCraft II:

- изучение Galaxy, NativeLib и GUI-библиотек реальной версии редактора;
- сопоставление XML-разметки Triggers с фактическим экспортом Galaxy;
- анализ ABI, типов, неявных аргументов событий, AUTOVAR и времени жизни loop-контекстов;
- минимальные примеры в Editor для отделения штатного GUI от runtime API;
- контроль полноты экспорта и порядка инициализации, даже если компиляция успешна;
- разбор MPQ/зависимостей, атрибутов и локализованных строк через используемые библиотеки.

Совпадение имени native в дампе не доказывает наличие GUI-обёртки. Близкое по названию действие не подменяет точную привязку без проверки ABI и поведения.
При доказанном отсутствии пригодной штатной GUI-привязки минимальное описание существующего API учитывается отдельно от новой runtime-функции. Исходный Custom Script сохраняется по выбранному режиму.

Использованы upstream-библиотеки [hometlt/modkit-extensions-blizzard](https://github.com/hometlt/modkit-extensions-blizzard) для работы с Blizzard/SC2-форматами. Благодарность [hometlt](https://github.com/hometlt) за upstream-код и техническую основу, использованные при разработке. Это указание реального происхождения зависимостей, а не приписывание ему всех локальных изменений или Editor/DLL-инструментов проекта.
Игровые бинарники, дампы машины и извлечённые игровые assets в эту публикацию не включены.
