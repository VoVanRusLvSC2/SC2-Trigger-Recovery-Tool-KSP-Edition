## 2. Методика

- **Входы.** Обоим конвертерам даётся копия карты без `Triggers` (`artifacts/modkit-vs-ksp-final-2026-09-26/maps`).
  Причина: KSP даже с `--generate-triggers-only-from-script` читает оригинальный `Triggers` как справочные метаданные
  (`withSourceMetadataTriggers` → `ReferenceMetadataBuilder`): восстанавливает из него типы, литералы, значения полей.
  На TTosh1 без оригинала KSP отказался (20 блокирующих ошибок типов), с оригиналом — выдал чистый результат.
  Modkit оригинал не читает: его вывод с оригиналом и без него побайтно одинаков.
- **Зависимости Ice Baneling проверены у обоих.** Modkit: Core → Liberty → Weather → кампании Liberty/Swarm/SwarmStory/Void →
  sweatr-SEF-Base → sweatr-SEF-IBE; все 4 библиотеки скрипта (`Ntve`, `SwaC`, `EBBC9C87`, `3FB28C60`). KSP: каталоги
  `197EC33E`, `3FB28C60`, `EBBC9C87`, `sefr`, `sfcm`, `sfgs` и стандартные из встроенного каталога.
- **`TextureMap.galaxy` (TM)** — два варианта (раздел 4): без него (копия карты без файла, `maps-no-texturemap`; оригинал
  не трогается — то же, что удалить на время конвертации) и с ним (Modkit — с включённой опцией `convertAdditionalScripts`,
  KSP переводит файл сам). KSP с TM — итоговый прогон 26.09 (не повторялся по решению владельца).
- **Каждое направление — отдельная команда в свежем процессе.** Galaxy→Triggers и Triggers→Galaxy измеряются раздельно:
  своё время и своя память. Galaxy→Triggers — один прогон (решение владельца); Triggers→Galaxy без TM — медиана трёх.
- **Время** — от запуска процесса до записанного результата: запуск, загрузка зависимостей, конвертация, запись.
- **Память** — пик суммы рабочих наборов всех процессов дерева (node, java, powershell-проба адаптера KSP, conhost) с опросом
  каждые 20 мс (`src/memory-monitor.ps1`); отдельно — пик выделенной (private) памяти дерева.
- **Совпадение Galaxy (AST)** — коэффициент Дайса по именованным узлам: функции, сигнатуры, глобальные объявления.
  Функция считается совпавшей, только если всё её дерево совпадает с оригиналом после нормализации форматирования.
  Эталон — оригинальный `MapScript.galaxy` (без TM).
- **Общий компилятор** — все `Triggers` (оригинала, Modkit, KSP) компилируются одним компилятором (Modkit Triggers→Galaxy после
  исправлений раздела 5), чтобы разница показывала качество самих Triggers. Настоящий эталон — компиляция в редакторе SC2,
  её делает только владелец.
- **Окружение и шум.** Intel Core Ultra 7 155U (14 потоков), 32 ГБ. Машина не была тихой: в окна замеров общая загрузка ЦП
  52–77%, из них Roblox 4–23%, Defender 3–12%; свободная память во время KSP опускалась до 0,4 ГБ (журнал —
  `.benchmark-runs/modkit-vs-ksp-final-2026-09-26.load.csv`). Время Modkit между одинаковыми запусками расходится до 1,7 раза,
  пик памяти node — до 1,5 раза (сборка мусора V8 при пределе кучи 8 ГиБ: два одинаковых по работе прогона дали 665 и
  999 МиБ). Разницу с KSP (в 100 раз по времени) шум не меняет.

## 4. `TextureMap.galaxy` и опция `convertAdditionalScripts`

Как подключается: `MapScript.galaxy` → `include "Lib3FB28C60"` → в `Triggers` мода sweatr-SEF-IBE элемент Custom Script
`include "sf/entry.galaxy"` → `sf/entry.galaxy` → `include "TextureMap"`; `sf/game/game.galaxy` вызывает `initTextureMap()`.
У мода есть свой `TextureMap.galaxy`; файл карты (4 086 строк: `string[2048] tm`, `initTextureMap()` с 2040 присваиваниями
`tm[i] = "…" + "…"`) его перекрывает. `MapScript.galaxy` файл не упоминает — это данные фреймворка мода, а не скрипт карты.

Поэтому перевод TM в триггеры карты неверен у обоих конвертеров:

- **Modkit (принудительно)** объявляет `tm` и `initTextureMap` в `MapScript` под теми же именами, что и файл, который
  подключает мод, — по правилам Galaxy это повторное объявление, карта не соберётся. Если файл удалить, мод подключит
  свой `TextureMap.galaxy`, и данные поверхности карты пропадут. К тому же код мода компилируется раньше кода карты.
- **KSP** переименовывает в `gv_tm`/`gf_initTextureMap`; их никто не вызывает — 4,2 МБ мёртвого кода в Triggers. Карта
  собирается, только пока файл остаётся в карте.
- Цена TM для KSP — +25,7 мин (постобработка +714 с, нормализация +477 с, вне стадий +419 с); для Modkit — +6,8 с.

Опция Modkit `convertAdditionalScripts` (по умолчанию выключена) теперь переводит только файлы, которые подключает сам
скрипт карты, прямо или через другой такой файл: текст файла встаёт на место его `include`, как его читает компилятор, файл
получает папку со своим именем, результат перечисляет его в `convertedScripts`, чтобы вызывающий удалил его из карты.
Файл, который скрипт карты не подключает, остаётся файлом с предупреждением `sc2-triggers/additional-script-not-included`.
Проверено на Ice Baneling (`.benchmark-runs/ice-baneling-tm-include-check-*`): TM остался файлом, `Triggers` побайтно
совпадают с колонкой «без TM». Опция нужна для скриптов, которые подключает карта (например, файлы ИИ `include "aiXXXX"`).

## 5. Ошибки Modkit

### Исправлено в этой сессии (рабочая копия `.wt-sc2-triggers-fix`, не закоммичено)

1. **Стартовый граф карты в CustomScript** (регрессия `2a014116`, задача 1 handoff). Карта, у которой `InitLibs` вызывает
   `InitLib` библиотек других пакетов, переводилась в режим `preserve`: `InitLibs/InitTriggers/InitGlobals/InitMap`
   становились пользовательскими функциями, каждый `gt_*_Init();` — отдельным CustomScript. Ice Baneling: 128 CustomScript
   (в оригинале 4), TTosh1: 121 (0), UoP: 27 (0). Теперь граф сворачивается; `InitLibs` восстанавливается по ссылкам
   элементов на библиотеки (`detectDependencies`, тот же, что у компилятора), а при расхождении с исходным списком выдаётся
   предупреждение `sc2-triggers/startup-libraries-differ`. Ice Baneling: CustomScript 4, совпадение Galaxy 100%.
2. **Нумерация пресетов-наследников в компиляторе Triggers→Galaxy.** Пресет с `PresetExtends` редактор нумерует с 10000
   (Ice Baneling: 6 пресетов, 51 значение), компилятор Modkit нумеровал с 0; `PresetExtends` не читался, не хранился и не
   писался. Теперь модель, чтение, запись и нумерация его учитывают. Оригинальный `Triggers` Ice Baneling компилируется в
   100% (было 92,7%).
3. **Сложение строк становилось целочисленной арифметикой.** Присваивание `s = "a" + "b"` строковой переменной или элементу
   массива через шаблон Set Variable давало Arithmetic (Integer) (`Ntve:00000128`) вместо Combine Strings (`Ntve:00000131`):
   тип цели не доходил до разбора `+`, а формальный тип значения Set Variable — `sameas`. Galaxy тот же (сравнение AST этого
   не видит), но редактор не примет целочисленную арифметику над строками. На TM: 2040 из 2040 → теперь Combine Strings.
4. **Опция `convertAdditionalScripts`** (раздел 4) — новая возможность, с проверкой подключения.

Тесты (без повышения прав, 26.09 23:08–23:40):
- `vitest.conversion.config.mjs` (conversion + spec): 714 из 716; 2 падения (`ttg-core.spec` «initializes non-default
  structure members…», `ttg-params.spec` «emits empty text only when…») такие же на чистом `8204e4ce` (710 из 712).
- owner-уровень `triggers` + `galaxy`: падает только `galaxy/test/workspace-file-system-index.test.ts` («refreshes changed and
  deleted workspace files…», утверждение libuv `fs-event.c` в воркере) — так же на чистом `8204e4ce`.
- Новые тесты: `triggers-galaxy-startup-validation` (стартовый граф), `triggers-galaxy-corpus-regressions` (`PresetExtends`),
  `triggers-galaxy-structured` (дополнительные скрипты и файл, который карта не подключает), `core/g2t-actions.spec`
  (сложение строк; без исправления падает: `ADD` вместо `COMBINE`).

### Не исправлено

5. **Библиотека карты не определяется по скрипту.** Берётся только из опции `libraryId`. Карты, чьи триггеры лежат в
   `<Library Id="1">` (AllRacesTester, KeyStone, AllRaces2-Tester и др.), сливаются в `Map`: имена теряют префикс `lib1_`,
   совпадение 0–0,1%.
6. **Неявная конверсия `unit → unitref`** превращается в «нативную» FunctionDef `UnitRefFromUnit` внутри карты, и компилятор
   выдаёт для неё лишний прототип (TTosh1). KSP это делает правильно.
7. **Пресеты-наследники в Galaxy→Triggers** пишутся обычными `int`-пресетами с явными значениями 10000…: компилируется
   правильно, но в GUI теряется связь с пресетом библиотеки (`PresetExtends`, `PresetInteger`).
8. **Комментарии и папки теряются**: Ice Baneling — 213 комментариев → 0, 24 папки → 5. Папка «Constants» не получает имя в
   `TriggerStrings`.
9. **Galaxy-объявления модов не подгружаются**: 1544 предупреждения «нет объявления» для `sf_*` (вызовы при этом привязаны
   к функциям библиотеки).
10. **Раскладка компилятора для карт**: «скрипт + `LibMap_h`» вместо одного `MapScript.galaxy`, из заголовка — лишний
    `include "TriggerLibs/natives"`.
11. **Загрузка зависимостей** — 40–50% времени Ice Baneling (задача 3 handoff).
12. Прочее из корпусного прогона: `galaxy-type-mismatch` (10 карт), 50-RealSteel — таймаут 15 мин, EditorTest.SC2Map — G2T
    упал, имена авто-переменных циклов (`auto<ID>`) не совпадают (задача 2).

Не ошибки: у Epic Bosses 152 из 1812 функций отличаются потому, что карту компилировал старый редактор (2014–2015): другие
переменные циклов (`int autoX_n; autoX_n = 10;` вместо `const int`), `init_i1` вместо `init_i`, попарная группировка сложения
текстов, старый шаблон «Pick Each Player». Текущий редактор при сохранении даст тот же код, что компилятор Modkit.

## 6. Ошибки и особенности KSP

1. **Теряет события библиотек модов** (Ice Baneling): все 72 восстановимых события `EBBC9C87` пропали; 57 триггеров остались
   без событий — карта из его Triggers неработоспособна, хотя его валидатор пишет `INTERNAL_CLEAN`.
2. **Втягивает данные фреймворка мода**: `TextureMap.galaxy` (4,2 МБ) → `gf_initTextureMap` и `gv_tm` в Triggers карты,
   мёртвый код (раздел 4).
3. **Теряет `PresetExtends`**: пресеты-наследники пишет `PresetInteger` без наследования — любой компилятор, включая
   редактор, пронумерует их с 0 вместо 10000 (51 константа Ice Baneling).
4. **Строгий Triggers→Galaxy** видит только встроенный каталог: на картах с модами (Ice Baneling: 29 251 блокирующая
   ошибка за 8,6 мин) и с кампанийными библиотеками (UoP: «No proven include ABI for dependency VCMI/VoiC») отказывается;
   с собственным CustomScript (TTosh1) — тоже.
5. **Падения**: AllRacesTester — `FATAL_GENERATION_FAILURE … PickEachInteger` через 24 мин (дважды); TTosh1 без
   оригинального Triggers — отказ после 305 с.
6. **Скорость**: Ice Baneling — 39 мин без TM и 65 мин с TM; разбор Galaxy ~22 мин в обоих случаях (раздел 8).
7. Правильно типизирует то, в чём ошибался Modkit: сложение строк (Combine Strings), `unit → unitref`. Сохраняет часть
   комментариев (8 из 213).

`benchmark.ice-baneling-4col-ksp-g2t.json` (KSP), затем `node src/t2g-crosscheck.mjs <прогон> --cases … --sources … --ksp-run …
--compilers … --run` (Triggers→Galaxy свежими процессами). Проверки этой сессии: `benchmark.ice-baneling-tm-include-check.json`
(TM остаётся файлом), `benchmark.ice-baneling-texturemap-as-script.json` (TM как скрипт: 2040 × Combine Strings),
`benchmark.ice-baneling-string-fix-check.json` (выход без TM не изменился). Разбор одного случая — `src/converter-comparison.mjs`.

## 10. Итоговая оценка

**Modkit** — точный и быстрый конвертер. Собственные Triggers компилируются обратно в тот же `MapScript.galaxy` (100% без TM),
сохранены все восстановимые триггеры и события, включая события библиотеки мода. Galaxy→Triggers в 100 раз быстрее KSP
(23,5 с против 39 мин), Triggers→Galaxy — 20 с, памяти 0,7–1,0 ГБ. Слабые места — оформление GUI: комментарии, папки,
связь пресетов с пресетами библиотеки, выключенные триггеры (последние не восстановит никто). Опасный класс ошибок — неверные
GUI-типы при верном Galaxy (сложение строк — исправлено, `UnitRefFromUnit` — нет): сравнение AST их не видит, нужен отдельный
контроль типов по `Triggers`. Библиотека `lib1` не определяется.

**KSP** даёт `INTERNAL_CLEAN`, но на карте с модом его Triggers неработоспособны: потеряны все события библиотеки мода
(57 триггеров без событий), совпадение Galaxy через общий компилятор 79%, собственный Triggers→Galaxy отказывает. 39–65 мин и
1,1–1,8 ГБ на карту, падения на части карт, зависимость от оригинального `Triggers` как подсказки. Полезен как оракул
отдельных случаев GUI-типизации (сложение строк, `unit → unitref`) и сохраняет часть комментариев.

Вывод: для карт с модами Modkit пригоден как основной конвертер, KSP — нет. Следующие задачи Modkit по порядку пользы:
библиотека карты по скрипту (`lib1`), комментарии и папки, `PresetExtends` в Galaxy→Triggers, `unit → unitref`,
контроль GUI-типов по `Triggers`.
