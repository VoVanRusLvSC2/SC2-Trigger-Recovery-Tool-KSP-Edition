R765–R779. 2026-10-23. Продолжение общей AST-поддержки и реальных карт.

1. Штатное событие TriggerAddEventUnitDamaged / Any Unit damage проверено через настоящий NativeLib: канонический callback и initializer восстанавливаются как GUI Event, без нового Native-описания; после SDK forward сохранены все 5 аргументов и единственная регистрация. Это отдельно от произвольной runtime-регистрации на явном trigger, для которой stock Event не предоставляет тот же контекст. UnitSetPropertyInt/Fixed и другие разные API здесь не приравнивались.

2. Основной распознаватель AoS R764 увидел 1316 из 1317 initializer; единственный пропуск gt_Cannibalize_Init вызван тем, что callback читает lv_hero до её последующей инициализации. Это исходное поведение, его не исправляли изменением игровой логики. V319 допускает такой prefix, если весь порядок GUI-инициализации совпадает с исходным. Парный сквозной пример R768: V318 отказывает, V319 сохраняет исходное раннее чтение и последующее присваивание, GUI Native0.

3. Полный AoS R769 на V319: прежний GUI_BINDING_INCOMPLETE 1317 сократился до 53, unresolved0. Из них 46 Param ссылок на исходные глобальные значения (25 color, 4 fixed, 10 int, 1 byte, 6 playergroup), 6 CustomScript metadata для исходных вызовов фазы InitCustomScript и один блок исходных глобальных объявлений. Нового PASS нет; упаковка, независимый packed-GUI gate и raw benchmark до следующего отказа не запускались. Документ AOS_INITIALIZER_DELTA_R779.json содержит именно фактический результат полной конвертации.

4. Дополнительно обнаружен небезопасный старый случай: source init-порядок later=global; early=later мог стать early=later; later=global после GUI-эмиссии. Парный тест R775 это воспроизвёл на V319. V320/V321 отказывают GUI_BINDING_INCOMPLETE вместо изменения прочитанного значения. Общая модель local-initializer-dependency-order.mjs сохраняет отношение read-before/read-after для каждой зависимости и не переставляет две потенциально наблюдаемые инициализации; независимые литеральные присваивания допускаются. Три теста включают обе стороны смены порядка чтения. Оригинальный порядок раннего чтения из п.2 остаётся поддерживаемым. Это усиление проверки, не ослабление oracle.

5. Haven R763 на V318 прошёл прежние raw GUI и source-only library отказы, но получил GUI_TYPE_ROLE_UNPROVEN у шести структурных чтений. Наблюдение R770 сохранило конкретные FunctionDef/ParamDef и входящие ссылки. Все шесть имели anycompare в ReturnType вместо типа объявленного поля. V320: expressionParameterType умеет уточнять отсутствующий/относительный тип результата по точно связанному исходному PropertyDeclaration и всем осям массива. Существующий номинальный GUI-домен/пресет сохраняется; неизвестное, static, локально затенённое или частичное агрегатное чтение не угадывается. Поиск члена также использует квалифицированный ключ структуры.

6. Первые тесты общей binding-only AST выявили реальный пропуск: оптимизированный getBinding не вычислял carrier, а проверка индекса массива ожидала int. V321 добавляет ленивый carrierAt на том же проверенном AST/checker. Тип вычисляется только при явном чтении carrier; обычная binding-индексация и сериализация отчёта не запускают type queries. Отсутствие SHA/чужой AST и неизвестный тип возвращают undefined; режим остаётся bindingOnly и не объявляется полной семантической проверкой. Два теста производительности/границ вызывают настоящий checker; два aggregate-теста проверяют полные оси и сохранение номинальных доменов.

7. Сквозной R775 для структурного сравнения прошёл с конкретным типом, Native0, без нового runtime-тела. Маленький пример проходил и на V319: он НЕ объявляется воспроизведением шести реальных отказов Haven. Для доказательства полного эффекта запущен Haven R777 на V321; актуальный итог хранится в REMAINING_SPACE_RETRY_R777.json. Ни этот тест, ни preflight не являются штатной Editor-компиляцией.

8. Capability для source-only startup дополнительно защищена: публичные строки доказательства заморожены, их изменение не может менять внутренние факты; full-GUI mode не может ссылаться на исходный owned payload как на сохранённое тело, если режим может его конвертировать. Два отрицательных теста прошли. Безопасные старые источники, production CURRENT/V193, прежние runtime-снимки и неизменяемый raw oracle сохранены. Новых Native, runtime-обёрток или CustomScript эти изменения не добавляют; уже разрешённые описания API учитываются отдельно в артефактах карты.
