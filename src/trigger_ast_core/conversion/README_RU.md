# Режимы восстановления GUI

Модульный вход: `trigger_ast_core/conversion/index.mjs`. Существующий EXE этой правкой не пересобирается.

```js
import {convertGalaxyToTriggers} from './trigger_ast_core/conversion/index.mjs';

// Обычный режим. Передаются настоящие исходники и метаданные зависимостей.
const result = await convertGalaxyToTriggers({
  ...verifiedInputs,
  existingTriggerData: originalTriggers, // если есть; иначе undefined
  additionalScripts: originalIncludedGalaxyFiles,
});

// Явная попытка перевести в GUI также отдельные включённые Galaxy-файлы.
const full = await convertGalaxyToTriggers({
  ...verifiedInputs,
  guiRecoveryMode: 'full-gui',
  additionalScripts: originalIncludedGalaxyFiles,
});
```

`preserve-source` используется по умолчанию. При наличии Triggers работает дозаполнение: исходные CustomScript, ScriptCode и Native-описания сохраняются с прежними типизированными ID, байтами XML и входящими ссылками. Независимые обычные GUI-функции можно добавлять и изменять. Если Triggers нет, обычные триггеры восстанавливаются с нуля. Новый исполняемый raw-код или Native-заглушка запрещены в обоих случаях.

Отдельные Galaxy-файлы в обычном режиме остаются исходниками и участвуют в разрешении имён. Они возвращаются в `output.preservedGalaxyScripts`; упаковщик обязан сохранить их по исходным путям. Это план упаковки, не доказательство записи архива. После упаковки необходимо отдельно сверить компоненты и запустить неизменённый бенчмарк.

Исходные ссылки `include` также сохраняются. Для них может понадобиться штатный CustomScript-элемент с одними исходными include. Разрешение привязано к AST исходного скрипта и SHA предоставленных файлов; добавить туда произвольный код нельзя. Такие элементы отдельно считаются в `sourceIncludeElements` и `newCustomScript`: ноль Custom Script для обычного режима не обещается. Дополнительная TTG-компиляция проверяет количество и порядок ссылок. Разрешение заканчивается вместе с операцией, в том числе для отложенных асинхронных действий.

`full-gui` включает существующий строгий перевод дополнительных включённых исходников. Итоговый GUI обязан иметь 0 Native, 0 CustomScript и 0 ScriptCode. Старый явный флаг `convertAdditionalScripts: true` остаётся совместимым с этим режимом; противоречащие друг другу настройки отклоняются. Само разрешение режима не обещает успеха: если имеющийся авторский Custom Script ещё нельзя перенести с сохранением дерева, конвертация завершается отказом. Скрытой полной перестройки существующего дерева или молчаливого сохранения raw-кода под статусом полного GUI нет.

В `guiRecovery` отдельно записываются режим, исходные и итоговые количества raw/Native, сохранённые ID и SHA. Это проверка происхождения и представления; она не меняет вердикт бенчмарка, не доказывает бизнес-эквивалентность и не заменяет Editor. Старые результаты полного GUI и список принятых карт автоматически не пересчитываются.

Инициализаторы различаются по происхождению и хранилищу. Неизменные исходные GUI-переменные используют правило Editor для `0/false/null`, когда оно согласуется с исходной функцией. Новые или изменённые переменные, неизвестные функции, явные записи в исходнике, массивы и структуры остаются под консервативной проверкой. Более поздняя запись локального значения в Actions не создаёт лишний reset перед условиями триггера. Runtime Actions этим механизмом не удаляются.

Доказательства происхождения передаются внутренним Symbol через `generationOptions` только внутри текущего процесса. JSON не содержит этого разрешения; следующий запуск восстанавливает его из переданных GUI и Galaxy. Это не кеш между запусками и не замена независимого сравнения скриптов.

Массовый строгий worker V178 явно выбирает `full-gui`: прежние 0/0 критерии корпуса остаются прежними. Обычный публичный API использует `preserve-source`. Кеш между запусками не добавлен.


Проверенная идентичность атрибутов документа (V190): `map_attributes/attribute_identity_context.mjs` создаёт краткоживущий контекст только по точному `.s2mh`, связанному с SHA исходного архива, namespace и каталогом ID/domain/value tokens фактического Attributes. Рабочий упаковщик подключает его автоматически при наличии такого источника. Обычный модульный клиент может передать внутренний Symbol `documentAttributeContext` вместе с созданным `createVerifiedDocumentAttributeContext` токеном. Перед генерацией из упакованной разметки каталог проверяется повторно.

Контекст возвращает namespace только типизированным собственным ID. Он не переписывает строки, внешних владельцев, неизвестные ID или runtime-токены значений. Без точного источника прежнее поведение сохраняется; namespace не угадывается. Контекст не доказывает defaults/лобби — они проверяются отдельно по архиву и полному Attributes. JSON не содержит разрешения, состояние не переносится между конвертациями.
