# Общие модули конвертера

Здесь находятся общие модели документов и скриптов, подсистема типов и GUI-выражений, проверки атрибутов. Это часть существующего AST-конвертера. Очереди карт, отчёты и тестовые примеры находятся за её пределами.

| Модуль | Ответственность |
|---|---|
| `types/expression-type.mjs` | Одна реализация определения типов по текущим областям видимости и реальным ссылкам библиотек |
| `gui/numeric-expression-contract.mjs` | Проверка грамматики, числовых типов, аргументов и исключительного владения слотами выражения |
| `gui/composed-expression-contract.mjs` | Совместная проверка числовых выражений и уже поддержанных локализованных текстовых слотов |
| `gui/numeric-remainder-builder.mjs` | Построение GUI-выражения с исходным `%`, без замены оператора или Native-обёртки |
| `gui/numeric-remainder-templates.mjs` | Транзакционное восстановление типизированного шаблона после разрешения всех ссылок |

Вариант `gui/remainder-templates.mjs` сохранён как зафиксированный контроль предыдущего целочисленного алгоритма V89. Текущая интеграция использует числовой модуль; выбора реализации по карте нет.

Основные ограничения:

- Названия карт, номера очереди и их хеши не участвуют в алгоритме. Они допустимы в тестах и манифестах доказательств.
- Определение типов не дублируется в выборе GUI-арифметики. Локальная переменная, параметр и глобальная переменная имеют различимые привязки; совпадение имени не заменяет привязку.
- Индексы живут внутри одного вызова конвертации; постоянного кеша нет. Замены применяются после проверки всей транзакции.
- Неизвестный тип, неоднозначная ссылка, исполняемый код в слоте или неправильное владение не получают исключение из строгой проверки.
- Исходный оператор и порядок вычислений сохраняются. Отсутствие raw-кода само по себе не доказывает эквивалентность карты.
- Производственный V65 и пользовательский ZIP-бенчмарк этим выделением не переключаются и не изменяются. Актуальный офлайн-кандидат и SHA доказательств указаны в `CURRENT.json`; исторические сборки сохранены.

Проверки и история находятся в `../queue_audit_2026-10-15`, `../offline_expression_type_core_contracts_20261017`, `../MAP_CODE_CHANGES_RU.txt` и `../MAP_CHANGELOG_RU.md`. Проверка Editor остаётся отдельным последующим этапом.

## Модель документа и атрибутов

`model/document-environment.mjs` — индекс одной неизменной фазы: документ, библиотека, тип, ID. После изменения набора определений индекс создаётся заново. XML-адаптер сохраняет исходные узлы и области видимости. Разные поставщики с совпадающими library ID нельзя молча объединять.

`model/program-environment.mjs` — один механизм разбора предоставленных root/include/CustomAI-файлов. Сейчас он используется в проверке атрибутов; остальные старые проходы конвертера ещё не переведены на эту модель.

Рабочий контракт атрибутов — `verification/attribute-recovery-gate.indexed.mjs`. Он объединяет сверку фактического Attributes, типизированных GUI-ссылок, подготовленных зависимостей и runtime-кода неизменённым пользовательским oracle. `attribute-program-contract.mjs` учитывает также косвенные обращения и API как значения. Старый `attribute-recovery-gate.mjs` сохранён для воспроизведения V133.

После создания job и его `config.json` общий офлайн-бенчмарк запускается так:

```powershell
node trigger_ast_core/verification/benchmark-generated-job.mjs <job> <новая-папка-отчёта>
```

Он вызывает прежний закреплённый бенчмарк и добавляет `BENCHMARK_WITH_ATTRIBUTES.json`. Основной вердикт не заменяется. Привязка результата к карте проверяется по SHA; REVIEW остаётся REVIEW. Сохранность восстановленной модели не означает доказательство полного исходного lobby. Новые тестовые defaults отмечаются отдельно.

План изменений, фактические замеры, отрицательные проверки и два реальных контрольных прогона: `../architecture_implementation_2026-10-18/IMPLEMENTATION_REPORT_RU.md`. Исходный аудит и следующие этапы: `../architecture_review_2026-10-18/ARCHITECTURE_REVIEW_RU.md`.

## Общая AST фазы преобразований

`model/galaxy-document.mjs` владеет текущим текстом и неизменяемой AST. Через `run` проход получает временный доступ `input/output`; изменение текста фиксируется только после успешной проверки. Ошибка оставляет прежнюю версию. `dispose` освобождает дерево после фазы. Документы и конвертации не разделяют состояние.

Десять существующих правил из `passes/` принимают такой доступ последним необязательным аргументом. Их семантические проверки и порядок сохранены. Главный скрипт и `lowering/owned-script-integer-operations.shared-ast.mjs` используют одну реализацию владения AST. Это пока не перенос всех стадий: внешние declarations, оставшиеся startup/loop-проходы и внутренняя генерация GUI ещё самостоятельны.

Проверки переноса: `../shared_ast_pipeline_2026-10-18/REPORT_RU.md`; квалифицированный entrypoint всегда определяется `CURRENT.json`. Независимый бенчмарк продолжает читать упакованные компоненты, а не доверять общей AST конвертера.
